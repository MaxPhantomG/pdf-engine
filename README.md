Представлена реализация первичного прототипа многопользовательского pdf-движка для обработки и хранения пдф документов
# Установка и запуск (линукс)
```
git clone git@github.com:MaxPhantomG/pdf-engine.git
cd pdf-engine
# полная очистка и пересоздание образа и базы(к старой доступ только у её создателя)
sudo docker-compose down -v
sudo docker system prune -a -f
sudo rm -rf postgres_data/
mkdir -p postgres_data
sudo chmod 777 postgres_data

# запуск образов + открытие веб-интерфейса
sudo docker-compose up --build
open http://localhost:8080
# open http://localhost:8000/docs (опционально если хочется открыть документацию по бэкенду)
```
# Функционал
* реализована регистрация и авторизация пользователей, через логин + пароль
* реализована загрузка пдф-документов в локальное хранилище
* каждый пользователь видит список документов которые загружены им и статусы загрузки
* между перезапусками сервер информация о пользователях и документах сохраняется
* все загрузки пдф-документов индексируются, имя документа и время загрузки сохраняются
* реализовано логирование
*  поиск по словам(реализован только веб-интерфейс, логика не реализована)

# Стэк технологий
- API:
  - FastAPI
  - uvicorn
- база данных(хранений пдф документо):
  - PostgreSQL
  - SQLAlchemy
- фоновыйворкер(обработка задач):
  - celery
  - redis
- docker(сборка проекта)


# Основные составляющие проекта и их взаимодействие
- **db**: база данных, хранит информацию о пользователях, документах и индексах
- **redis**: выполняет задачи фонового воркера(загрузка пдф)
- **backend**: принимает HTTP-запросы от фронтенда, управляет бизнес-логикой, взаимодействует с бд, отправляет фоновые задачи в Celery.
- **frontend**: пердоставляет веб-интерфейс, обращается через http-запросы к api бэкенда
- **worker**: получает фоновые задачи, читает/обновляет данные в БД (через сессии SQLAlchemy)
